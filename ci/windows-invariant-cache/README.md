# Windows invariant build cache pilot

Read-only branch experiment, same runner only, x64. Cold build uses exactly the production MSVC/SDK/mitigation configuration; preserve patched SDK tree, SQLite static library, intermediates, PDBs and generated SQLite headers. Copy with preserved times (bounded four transfer workers); hash every file with four bounded workers, remove and restore tree to identical paths, compare manifests, delete first-party output/intermediate trees, invoke MSBuild Build instead of Rebuild. Require zero SQLite and SDK source compile records, fresh first-party source compile records, unchanged library digests and native worker contracts. Benchmark cold, snapshot/hash, restore/hash, warm. This is not a trusted cross-job cache, release build, or complete PE qualification. No external cache publication and no change to required workflows. Do not publish SDK contents without license review. Next if useful: exact context keys (actual compiler, imports, SDK/STL/header closure, configuration), separate SDK/SQLite archive artifacts, signed trusted producer mapping, read-only restore, preserved PDB lineage and full six-PE BinSkim/source attribution. Avoid blind cache of the full MSBuild tree in production. MSBuild tlogs already track compile dependencies; evaluate portable Bazel aquery/CAS or CMake/Ninja compiler launcher separately rather than migrate production toolchain prematurely.
