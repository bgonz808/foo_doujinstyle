# Dependency proposals and promotion

Dependabot owns GitHub Actions version proposals. Renovate is restricted to Dockerfile image digests; app installation/authorization and extraction validation required separately. No automerge, no duplicate ownership. Ubuntu noble tag is descriptive; existing digest remains authoritative; base and snapshot compatibility reviewed jointly. No privileged bot workflow or arbitrary post-upgrade command.

For Actions, review exact upstream commit and runtime dependencies; update all callsites and the explicit SHA approval map in tools/security_audit.py only after review. Bot-created SHA changes intentionally fail until approved. Minimum upstream release age is seven days by default. Dependabot cooldown is a proposal throttle, not an independent security guarantee. Renovate uses minimumReleaseAge=7 days with timestamp-required behavior; digest timestamps are not universally available, so separately verify publication time before promotion and hold unknown-age candidates for explicit review. Qualification and approval remain separate requirements. Urgent security fixes can receive an explicit documented minimum-age exception. No additional post-qualification waiting period is implied.

For custom LLVM, SDK, actionlint, vendored sources and hash-locked Python wheels: candidate discovery is separate from reviewed atomic version/URL/platform SHA256/expected binary or closure hash updates. Preserve hash enforcement and run all relevant gates. Follow-up canonical artifact locks and resolver #60; do not claim automated coverage before first verified bot runs. Use apko lock regeneration, not independent version-only edits to generated package locks. Shared producer and consumers must distinguish candidate from promoted digest. No automated trust promotion.

## Expedited minimum-release-age exceptions

Minimum age is an eligibility condition, never a substitute for security qualification. Evaluate the **last qualified, age-compliant immutable baseline** and the exact candidate under the same current advisory database, policy, scanner versions and configuration; "clean" means no disallowed known findings under recorded coverage, not proof of malware absence. For an already expedited baseline, also retain the cumulative delta from the last fully age-compliant baseline; do not reset the trust anchor or age clock by chaining exceptions.

1. Record specific vulnerability/advisory or other urgent operational justification, affected package and exact current/candidate digests, exposure/exploitability (including VEX rationale), fix evidence, upstream publication timestamp, exception expiry and independent approver. Unknown timestamps are held for review, not automatically eligible.
2. Resolve the smallest supported remediation on the baseline closure (targeted patch/backport or exact vendor security revision where practical). Freeze unrelated dependency updates; compare complete resolved lock, package hashes, repositories, signing keys, platform and build recipe. If transitive changes are required, enumerate them and independently justify/age-check each; do not blanket-exempt an image.
3. Compare normalized SBOMs by package URL/version/hash and dependency relationships; include new, removed, changed and same-version-different-hash packages. Scan baseline and candidate against the same current DB snapshot, independently verify target remediation, assess all introduced/worsened findings, existing residuals and coverage gaps. Disallow new policy-violating findings; absence of a new CVE is not evidence against malware.
4. Review upstream source and packaging changes across the exact old/new commits (including intervening changes, build scripts, generated files, dependencies, patches, install hooks, maintainer/signing changes and unexpected binaries). Verify signed release/provenance and source-to-artifact binding, independently reproduce or compare build output where feasible. Inspect filesystem delta (path, digest, owner/mode, executable bits, symlinks, setuid/capabilities), OCI config/entrypoint/env/layers and executable imports/behavior. Run appropriate secret/malware checks and isolated differential behavior tests. Unknown or unexplained changes block automatic promotion; prefer a narrow vendor backport or maintained alternative over accepting broad opaque deltas.
5. Run all applicable build, analyzer, hardening, functional, negative and integration gates. Retain immutable evidence and require independent approval for expedited promotion; no bot automerge, no relaxed integrity/provenance checks, no trusted credentials exposed to candidates. If required assurance cannot be obtained, keep baseline with compensating containment or disable affected functionality, or explicitly escalate residual risk to authorized owner rather than silently waive.
6. Issue a scoped exception bound to baseline/candidate digests, package identities, allowed deltas, advisory/justification, review evidence, policy revision, approver and expiry. Expiry governs authorization, not automatic rollback to vulnerable software: re-evaluate, renew explicitly or promote a normally eligible qualified candidate. Revoke on new adverse evidence; keep safe rollback/containment options. Re-evaluate cumulative deltas until all promoted inputs meet age policy.

The first implementation is policy documentation only. A machine-enforced, signed exception schema and delta evaluator belong in the shared update-analysis project; use existing SBOM/SCA, provenance and diff tools, not a new scanner. Independent approval governance remains #32; this document grants no override or promotion authority.

## Standing CI performance audit
Every Actions/workflow/runner audit must inspect both end-to-end workflow critical-path time (including queue and setup) and every job/step over 20 seconds; recurring tool acquisition target 15 seconds. Break slow steps into actual nested work: download, resolution, verification, extraction, compile/link, per-TU analysis, test, cache, artifact transfer, attestation and teardown. Inspect runner image, CPU/memory, contention and concurrency; distinguish summed task times from elapsed critical path. Ask whether each dependency, step and repeated computation is needed, whether immutable inputs can be reused safely, and whether independent work can overlap. Flag unexplained regressions, stalls, redundant dependencies and retries even when checks pass. Record measured timings, bottleneck, evidence links, disposition (fix now, justified necessary work, or explicitly tracked backlog), and cold/warm variance; no arbitrary timeout or weakened test/security coverage to hit latency targets. Limit new optimization scope to concrete turnaround risks; do not indefinitely defer native migration for speculative research. Close scoped issues only when accepted work is merged and verified; preserve outstanding work under #59/#60 or an appropriate existing ticket.
