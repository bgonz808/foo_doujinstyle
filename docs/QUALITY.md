# Quality evidence and runner responsibilities

## Scope and commands

Portable CI emits JUnit from the existing deduplicated unittest invocation, not a second run. The opt-in Wolfi experiment instruments only the publisher's first-party C++ translation units with Clang source coverage, runs the same canonical suite once, and exports line/function/branch/region denominators and source/binary digests. The regular Ubuntu build retains its existing noninstrumented behavior and reports coverage null. Windows DLL and actual host coverage are null until a source-bound instrumented Windows host run. The publisher coverage denominator is not the repository or entire component; facet executable, vendored C/SQLite, Windows-only DLL and uninstrumented code are excluded. Skipped tests are not passed; failed subtests are retained under canonical parent identity. Local source-tested result is not release qualification.

Run bash tools/test_portable.sh in a prepared Linux environment. For instrumented run use a clean build directory and PORTABLE_COVERAGE=1; matching llvm-profdata/llvm-cov and compiler-rt required. Invoke python3 -m tools.quality.coverage as in the Wolfi workflow. Report with tools.quality.report and tools.quality.viewer (or local composite action). No Python dependencies, CDN or JavaScript required. Published bundle is sanitized JUnit, JSON, LCOV relative source paths, Markdown and HTML, not raw profiles, executables or exception payloads. CI checks current checkout source identity and coverage source/binary hashes; report view verifies input hashes. This is same-job evidence, not a signed cross-job trust assertion. Fixture/source manifest provenance, Windows DLL coverage and host evidence ingestion remain follow-up under #42/#33. Do not combine denominators across binaries.

## Runner split and recurring cost

Linux retains fast independent portable contracts and Clang analysis; Windows builds and qualifies actual DLL/worker/PE/ABI and eventually GUI/ETW/audio behavior. Some preflight tests overlap; identify exact test IDs before removing duplication. Dedicated host-trace contracts are cheap and validate non-GUI invariants. Windows ETW build is separately instrumented; do not use production or ETW artifact interchangeably. Ordinary Linux and Wolfi are not intended to run two equivalent suites indefinitely: Wolfi is optional qualification until immutable image promotion. Keep Linux vs Windows differing behavior coverage, not duplicated test execution for its own sake. Consider shared trusted SDK/object cache, prequalified Windows snapshots and qualified OCI toolchain. #59 documents benchmark and trust boundaries. Audit >20s workflow/job/step, >15s recurring acquisition; report instrumentation, execution, collection, rendering and upload costs. Do not remove security gates for speed.

Related: #42, #33, #17, #22, #1, #59. This first extraction deliberately preserves current Windows build and all required checks.
